# Модуль построения транспортно-логистического графа (Python Backend)

Модуль отвечает за извлечение дорожной топологии OpenStreetMap, привязку логистических объектов (склады, порты, терминалы) к дорожной сети, расчет кратчайших автомобильных маршрутов и формирование специализированного **логистического графа** для ML и Frontend.

---

## 🚀 Быстрый запуск

### 1. Подготовка окружения
```bash
cd backend/python
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Запуск пайплайна

#### А. Демонстрационный запуск (Кронштадт / Шушары)
```bash
# Базовый запуск на полигоне Кронштадта:
python main.py

# Разреживание логистического графа (k=2 ближайших соседа):
python main.py --knn 2

# Запуск на логистическом кластере Шушары:
python main.py --shushary --knn 3
```

#### Б. Анализ произвольной территории по BBox
```bash
python main.py --bbox 59.98 29.68 60.03 29.82 --knn 2
```

#### В. Прямой вызов через контракт интеграции с Go-бэкендом
```bash
python main.py --input-json data/example_request.json --output-json data/example_response.json
```

Опциональные флаги запуска:
* `--bbox min_lat min_lon max_lat max_lon` — границы исследуемой территории (Bounding Box).
* `--place <название>` — произвольная территория для геокодирования OSM (например: `'Выборг, Россия'`).
* `--facilities-file <путь.json>` — пользовательский файл со списком логистических объектов.
* `--input-json <запрос.json>` — вызов пайплайна через DTO-контракт Go-бэкенда (`AnalysisRequest`).
* `--output-json <ответ.json>` — сохранение структурированного ответа (`AnalysisResponse`).
* `--refetch` — принудительно заново скачать дорожную сеть из OpenStreetMap (минуя локальный кэш).
* `--osm-pois` — автопоиск логистических/промышленных POI в границах территории через Overpass API.
* `--knn <K>` — разреживание связей графа методом k-ближайших соседей.

### 3. Запуск тестов (100% оффлайн)
Тесты проверяют валидацию, оффлайн-построение графа и обработку ошибок без обращения к сети:
```bash
pytest tests/
# или стандартным раннером:
python -m unittest discover tests
```

  * Сохранение и оффлайн-загрузка графа дорог (`save_graphml`, `load_graphml`).
  * Экспорт дорожного слоя в GeoJSON (`export_to_geojson`).
* [`services/facility_service.py`](file:///Users/kiryakhamentry/Desktop/Coding/Project/regional-transport-analytics/backend/python/services/facility_service.py) — **`FacilityService`**:
  * Парсинг и строгая валидация пользовательских объектов (`parse_and_validate_facilities`).
  * Автопоиск объектов в OSM по BBox (`fetch_from_osm_bbox`) и названию (`fetch_from_osm`).
  * Многоточечная привязка (Multi-point Snapping до 5 кандидатов) к узлам дорожной сети (`snap_to_road_network`).
* [`services/logistics_graph_service.py`](file:///Users/kiryakhamentry/Desktop/Coding/Project/regional-transport-analytics/backend/python/services/logistics_graph_service.py) — **`LogisticsGraphService`**:
  * Расчет кратчайших автомобильных путей Door-to-Door и синтез логистического MultiGraph (`build_logistics_graph`).
  * Разреживание графа методом k-NN (`k_neighbors`).
  * Склейка геометрии дорог и генерация пунктирных коннекторов последней мили (`access_connector`).
  * Сериализация в GraphML и экспорт в GeoJSON (`save_graphml`, `export_to_geojson`).
* [`graph_service.py`](file:///Users/kiryakhamentry/Desktop/Coding/Project/regional-transport-analytics/backend/python/graph_service.py) — **`GraphService`**:
  * Фасад (Facade) для обратной совместимости, объединяющий все сервисы под единым интерфейсом.

## 🗺 Концепция данных

Модуль оперирует двумя концептуальными уровнями графов:

1. **Дорожный граф (Road Network Graph)**:
   * Физическая дорожная сеть OSM (сотни/тысячи перекрестков и дорожных сегментов).
   * Используется как подложка для точной автомобильной маршрутизации с учетом одностороннего движения.
   * Формат: `data/kronshtadt_network.graphml` и `data/kronshtadt_network.geojson`.

2. **Логистический граф (Logistics MultiGraph)**:
   * Ненаправленный мультиграф (`nx.MultiGraph`), связывающий ключевые хабы региона в соответствии со спецификацией PM/DS.
   * **Вершины (`LogisticsNode`)**: самостоятельные логистические объекты со свойствами (`id`, `name`, `object_type`, `latitude`, `longitude`, `region_ids`, `verification_status`, `transport_modes`, `nearest_osm_node`, `snap_distance_m`).
   * **Рёбра (`LogisticsEdge`)**: одно логическое ребро на вид транспорта (`road`) между парой объектов `(node_a, node_b)`, содержащее раздельные характеристики направлений `A ➔ B` и `B ➔ A` (`distance_ab_m`/`distance_ba_m`, `route_status_ab`/`route_status_ba`, `geometry_ab_wkt`/`geometry_ba_wkt`).
   * Формат: 
     * `data/kronshtadt_logistics.graphml` — для ML-модуля (анализ топологии, метрики связности).
     * `data/kronshtadt_logistics.geojson` — для визуализации на фронтенде (маркеры хабов с плечами привязки + линии маршрутов).

## 📂 Структура тестовых данных

### Входные логистические точки (`data/test_logistics_points.json`)
```json
[
  {
    "id": "hub_merch_port",
    "name": "Купеческая гавань (Портовый терминал)",
    "lat": 59.9882,
    "lon": 29.7712,
    "type": "port"
  },
  ...
]
```

### Выходной GeoJSON (`data/kronshtadt_logistics.geojson`)
Содержит `FeatureCollection` из двух типов объектов:
* `logistics_hub` (`Point`) — маркеры хабов с координатами и названиями.
* `transport_route` (`LineString`) — реальные линии автомобильных маршрутов с атрибутами дистанции (`distance_m`), точек дорог (`osm_nodes_count`) и подсказкой (`title`).
