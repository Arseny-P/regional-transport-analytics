
# Модуль расчёта графовых метрик

Модуль `metrics_service.py` предназначен для анализа транспортной доступности и связности логистических объектов.

## Реализованные метрики

### Общие характеристики графа

- `node_count` — количество логистических объектов.
- `edge_count` — количество уникальных пар объектов, между которыми найден хотя бы один маршрут.
- `directed_route_count` — количество направленных маршрутов.
- `component_count` — количество слабых компонент связности.

### Метрики отдельных объектов

- `reachable_count` — количество других объектов, достижимых из данной вершины.
- `average_distance_m` — средняя длина кратчайших маршрутов до достижимых объектов, в метрах.
- `weighted_closeness` — взвешенная центральность близости по исходящим маршрутам с поправкой на недостижимые объекты.

## Особенности реализации

- Учитываются направления движения `A → B` и `B → A`.
- Используются длины маршрутов, полученные при построении транспортно-логистического графа.
- Кратчайшие пути рассчитываются алгоритмом Дейкстры.
- Отсутствующие, неположительные и некорректные расстояния исключаются.
- При нескольких связях между одной направленной парой объектов выбирается минимальное расстояние.
- Если из объекта нельзя добраться ни до одного другого, `average_distance_m` принимает значение `null` в JSON, а `weighted_closeness` — `0`.

## Пример использования

Запуск из каталога `backend/python`:

```python
import json
import networkx as nx

from services.metrics_service import calculate_metrics_report

graph = nx.read_graphml("data/kronshtadt_logistics.graphml")
report = calculate_metrics_report(graph)

with open("data/kronshtadt_metrics_result.json", "w", encoding="utf-8") as f:
    json.dump(report, f, ensure_ascii=False, indent=2)
```

Для примера используется граф Кронштадта, предварительно созданный Python-модулем.

## Тестирование

Из каталога `backend/python` выполнить:

```bash
python -m unittest test_metrics_service.py -v
```

Реализованы пять автоматических тестов:

1. Проверка общих характеристик графа.
2. Проверка метрик отдельных объектов.
3. Проверка направлений маршрутов.
4. Обработка некорректных расстояний.
5. Обработка нескольких маршрутов между объектами.

## Примеры результатов

- `data/metrics_result.json` — результаты на тестовом графе из 4 объектов.
- `data/kronshtadt_metrics_result.json` — результаты на графе Кронштадта из 5 объектов.

Отчёт содержит два раздела:

- `graph_metrics` — общие характеристики графа;
- `node_metrics` — показатели доступности каждого логистического объекта.

## Текущее состояние

Модуль реализован и протестирован отдельно от основного Python-бэкенда.

Проверена работа на тестовом графе и на графе Кронштадта, построенном на данных OSM.

Интеграция модуля в общий процесс обработки запросов пока не выполнялась. Код находится в отдельной ветке `feat/28-graph-metrics` и не изменяет основную ветку проекта.
